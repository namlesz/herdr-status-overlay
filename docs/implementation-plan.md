# Implementacja — plugin i helper API (aktualny kierunek)

Użytkownik odrzucił patch/przebudowę Herdr i zatwierdził plugin uruchamiający natywny helper oraz własną listę zakończeń opartą na `completion_seq`. Stara specyfikacja eksportera `docs/specs/status-overlay-design.md` jest historyczna tam, gdzie koliduje z tym dokumentem. Bez instalowania pluginu, zmiany configów ani uruchamiania GUI bez osobnego uzgodnienia.

## Zakres implementacji

- Plugin macOS `local.status-overlay`: akcja otwiera jego własny panel w tle (`--no-focus`), helper pozostaje procesem pierwszoplanowym tego panelu. Nie używać startup hook, `open`, `nohup`, odłączania ani nadzoru przez daemon. Zamknięcie panelu/SIGHUP/SIGTERM i Quit kończą helper oraz jego odczyty, nie agentów. Nie modyfikować Herdr.
- Helper Swift/AppKit jako executable, bez osobnej instalacji `.app`, bez Docka. Publiczne flagi NSPanel z §8 starego specu, menu show/hide/quit i ręczne potwierdzenie własnych zakończeń. Jeden panel, zapamiętana pozycja/widoczność, monitor fallback, wysokość ≤40% widocznego ekranu, scroll i tekstowe statusy, dostępne kontrolki. Heartbeat bez zmian danych nie przebudowuje UI. Zweryfikować tylko build; GUI nie uruchamiać automatycznie.
- Jeden lokalny session socket z `HERDR_SOCKET_PATH` kontekstu pluginu; remote z jawnej listy aliasów zapisanych maszyn w configu pluginu. Brak skanowania wszystkich maszyn i brak własnego SSH. Nie hardkodować aliasu użytkownika. Podać przykład configu i bezpieczną obsługę pustej listy. `HERDR_BIN_PATH` jako executable, argv zamiast shell.
- Odczyt local: `herdr agent list`, remote: `herdr --machine <alias> agent list`. Nigdy --remote, add, reconnect, update/handoff ani server start/stop. Local co 2 s, remote 5 s po zakończeniu poprzedniego odczytu; najwyżej jeden proces na źródło. Timeout 10 s, ograniczenie stdout 1 MiB i stderr do małego bufora bez logowania zawartości, zamknięcie/kontrolowane zakończenie dzieci. Brak kolejki odczytów i brak pipe deadlock. stdin /dev/null. Brak interaktywnego uwierzytelniania. Po błędzie backoff 5/10/30 s.
- Sekcje per źródło (lokalna sesja / zapisany alias), nigdy per klient. Nie utożsamiać różnych źródeł ani nie pokazywać globalnej sumy. Pięć liczników, wiersze blocked i własne done z nazwą, maszyną i workspace, stabilne sortowanie. Używać dostępnych etykiet API i bezpiecznych fallbacków publicznych ID; nie eksportować/logować cwd, komend, tytułów terminala ani payloadów. Nieznane pola API ignorować, typy/statusy/duplikaty/wielkość walidować, etykiety sanityzować C0/C1/DEL/U+2028/U+2029 i przycinać UTF8 do 1024 B.
- Świeżość od pomyślnego odczytu, nie od renderu. Błąd/timeout od razu oznacza dane stale. Zegar mach_continuous_time; local stale po 6 s, remote po 20 s; po 60 s cache usuwany, lecz skonfigurowana sekcja pozostaje z komunikatem braku danych. Stale wykluczone z liczników (— zamiast zer). Wake natychmiast unieważnia dane i wynik odczytu rozpoczętego przed sleep; nowy odczyt ustala baseline.

## Własne zakończenia — nie klientowe done/seen

- `completion_seq` to nie liczba zadań! Jest znacznikiem zakończenia w domenie sekwencji Herdr. Wzrost 135→141 nie oznacza sześciu zakończeń. Test live local uchwycił working→idle i zmianę znacznika przy `focused:false` przez cały czas; samo API pozostało idle.
- Pierwszy poprawny snapshot jest baseline: nie oznaczać wszystkich zastanych idle jako nowych zakończeń. Brak completion_seq podczas working nie usuwa wcześniej znanego znacznika. Jeśli agent był obserwowany jako working i następnie pojawia się pierwszy znacznik zakończenia, można zarejestrować zakończenie. Późniejszy większy znacznik oznacza nowe zakończenie także bez uchwycenia working między odczytami.
- Tożsamość agentów co najmniej source + pane_id + terminal_id (jeżeli dostępny). Spadek sekwencji, wymiana tożsamości, usunięcie z pełnego snapshotu lub odzyskanie źródła po błędzie/wake resetują baseline bez fałszywego zakończenia. Nie obiecywać wykrycia restartu pomiędzy dwoma bezbłędnymi odczytami bez jawnego boot_id; sprawdzić dostępność znacznika epoki w odpowiedzi i udokumentować ograniczenie jeśli go brak.
- Własny stan oczekującego zakończenia przechowywać tylko w pamięci. Potwierdzenie w overlayu nie wywołuje focus/ack/input Herdr. working/blocked/unknown mają pierwszeństwo przed własnym done; przy idle lub serwerowym done efektywny status to własne done wyłącznie gdy jest oczekujące zakończenie, w przeciwnym razie idle. W UI jasno opisać, że done jest listą overlayu.
- Bez kumulowania historii każdej tury: najwyżej jeden oczekujący rekord na aktualnego agenta.

## Weryfikacja i granice

- Standardowa komenda headless, bez Herdr/GUI/SSH. Lokalny CLT Swift 6.4 nie udostępnia XCTest (`swift test` zakończył się błędem importu), więc zapewnić executable self-check lub równoważne działające testy bez zależności. Nie zachowywać niedziałających testów jako deklaracji sukcesu.
- Testy: parser allowlista/błędne typy/duplikaty/rozmiar, full replacement, completion baseline/change/missing while working/reset/identity/remove/ack, stale/retention/wake, niezależność źródeł, odczyty fake subprocess (timeout, slow reader, oversized stdout, stderr flood, kill, no overlap). Testy nie używają rzeczywistego Herdr/SSH i nie otwierają GUI. Build z deployment target macOS 13.
- Usunąć martwy exporter IPC/listener/fixtury NDJSON ze starego szkieletu zamiast utrzymywać dwie architektury. Nie usuwać dokumentów użytkownika. Zachować testy, które mają sens, przepisując je na aktualny model.
- Dokumentacja: setup/build, plugin link/konfiguracja/uruchomienie dopiero przez użytkownika lub za zgodą, rzeczywiste ograniczenia macOS/Intel/GUI i brak gotowego odbioru live. Zapis nierozwiązanych usterek oraz konkretnych niewykonanych testów natywnych w docs/backlog.md i docs/pending-live-tests.md.
- Repo nie ma commitów HEAD: istniejące pliki są untracked. Nie commitować/pushować/resetować ani nie zmieniać gałęzi. `.pi/` i wygenerowane buildy nie są produktem.
- Świeżokontekstowe review całości ryzykownego kodu przed uznaniem implementacji za gotową. Wyniki review zweryfikować i ponowić dotknięte testy. Nie instalować pluginu i nie uruchamiać nowego testu live remote/GUI w ramach samego kodowania.
